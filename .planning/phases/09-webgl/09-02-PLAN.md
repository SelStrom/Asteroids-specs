  <action>
Выполнить следующую последовательность git-команд из корня проекта:

```bash
cd /Users/selstrom/work/projects/asteroids-specs

# 1. Проверить что Build/WebGL существует (результат 09-01)
ls Build/WebGL/index.html
ls Build/WebGL/Build/*.wasm

# 2. Сохранить текущую ветку
CURRENT_BRANCH=$(git rev-parse --abbrev-ref HEAD)
echo "Текущая ветка: $CURRENT_BRANCH"

# 3. Использовать worktree для безопасного создания gh-pages
# (не нужно переключать ветку в рабочей директории)
DEPLOY_DIR="/tmp/asteroids-gh-pages-deploy"
rm -rf "$DEPLOY_DIR"

# 4. Проверить существует ли ветка gh-pages
if git show-ref --quiet refs/heads/gh-pages; then
    echo "Ветка gh-pages существует, добавляем worktree"
    git worktree add "$DEPLOY_DIR" gh-pages
else
    echo "Ветка gh-pages не существует, создаём orphan"
    git worktree add --orphan -b gh-pages "$DEPLOY_DIR"
fi

# 5. Перейти в worktree и очистить
cd "$DEPLOY_DIR"
git rm -rf . --quiet 2>/dev/null || true

# 6. Скопировать файлы сборки
cp -r /Users/selstrom/work/projects/asteroids-specs/Build/WebGL/. .

# 7. КРИТИЧНО: создать .nojekyll (пустой файл)
touch .nojekyll

# 8. Проверить структуру перед коммитом
echo "Структура деплоя:"
ls -la
echo "Build/ папка:"
ls Build/

# 9. Закоммитить и запушить
git add -A
git commit -m "deploy: WebGL build — Asteroids v1.0"
git push origin gh-pages --force

# 10. Вернуться и убрать worktree
cd /Users/selstrom/work/projects/asteroids-specs
git worktree remove "$DEPLOY_DIR" --force
```

ВАЖНО: После `git push` вернуться в основную директорию проекта.
Флаг `--force` нужен при первом деплое orphan-ветки. При последующих обновлениях — обычный push.

  <how-to-verify>
**Шаг 1 — Открыть настройки репозитория:**
1. Открыть в браузере: https://github.com/SelStrom/Asteroids-specs/settings/pages
2. (или: репозиторий → вкладка `Settings` → раздел `Pages` в левом меню)

**Шаг 2 — Настроить источник:**
1. В разделе `Build and deployment` → `Source` выбрать `Deploy from a branch`
2. В поле `Branch` выбрать `gh-pages`
3. В поле папки оставить `/ (root)`
4. Нажать `Save`

**Шаг 3 — Дождаться публикации:**
1. GitHub покажет сообщение: "Your site is being published"
2. Подождать 1-3 минуты
3. Обновить страницу Settings → Pages
4. Должна появиться ссылка: `Your site is live at https://selstrom.github.io/asteroids-specs/`

**Шаг 4 — Проверить работу игры:**
1. Открыть URL: https://selstrom.github.io/asteroids-specs/
2. Дождаться загрузки (прогресс-бар Unity, может занять 30-60 секунд — файлы несжатые)
3. Убедиться что игра запустилась:
   - Появился экран Title с надписью ASTEROIDS
   - Клавиша Enter / пробел запускает игру
   - Корабль управляется (WASD/стрелки)

**Признаки успеха:**
- URL открывается (не 404)
- Прогресс-бар Unity заполняется и исчезает
- Игровой экран отображается

**Признаки проблем:**
- 404 → GitHub Pages ещё не опубликован (подождать 5 минут, проверить настройку Branch)
- Чёрный экран / прогресс-бар застыл → открыть DevTools (F12) → вкладка Console, сообщить об ошибках
- 404 на .wasm файлы в Network tab → .nojekyll не сработал (проверить `git show gh-pages:.nojekyll`)
