# Quick Task 260328-3p1: Fix GameOverScreen Duplication and NullReference Summary

**One-liner:** Исправлены два бага в Editor Setup — поиск неактивных GameOverScreen через FindObjectsOfType и назначение UserGunData в GameData.Ship.Gun через SerializedObject.

## Objective

Устранить два бага в Editor Setup скриптах:
1. GameOverScreen дублировался при повторном запуске `Asteroids > Setup Phase 4 Assets`
2. NullReferenceException в GunSystem при Play — `gun.Config` равен null

## Changes Made

### Task 1 — Phase4Setup.cs: FindObjectsOfType вместо GameObject.Find

**Проблема:** `GameObject.Find("GameOverScreen")` не находит неактивные объекты. GameOverScreen создаётся с `SetActive(false)`, поэтому при повторном запуске Setup старый объект не находится и не удаляется — создаётся дубликат.

**Решение:** Заменить на `Object.FindObjectsOfType<GameOverView>(true)` с параметром `includeInactive=true`. Удалять все найденные GameOverView перед созданием нового.

### Task 2 — Phase3Setup.cs: Назначение UserGunData в Ship.Gun

**Проблема:** `CreateConfigAssets()` создавал `UserGunData.asset` и `GameData.asset` по отдельности, но не назначал `UserGunData` в `gameData.Ship.Gun`. В результате `configs.Ship.Gun == null`, `ShipModel.Setup()` создавал `new GunComponent(null)`, и `GunSystem.UpdateNode()` падал на `gun.Config.MaxShoots`.

**Решение:** После `CreateOrReplaceAsset(gameData, ...)` загрузить оба ассета через `AssetDatabase.LoadAssetAtPath`, назначить через `SerializedObject.FindProperty("Ship").FindPropertyRelative("Gun").objectReferenceValue = savedUserGun`.

**Причина двух шагов:** `GunData` — это `ScriptableObject` (ссылочный тип) внутри `ShipData` (struct). Прямое присваивание до сохранения ассета теряется при сериализации — нужно загружать сохранённый ассет и использовать `SerializedObject`.
